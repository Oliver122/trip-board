# Step 28 — Board admins, custom spot kinds and single-use invites

**Goal:** the owner of *Japan 2026* makes `aiko` a board admin; she adds a kind “Food” in orange next to *Must go* and *Maybe*, and a planner can then pick “Food” for “Ichiran Ramen”, whose pin, list strip and filter chip show orange; a spot can also be both “Food” and *Must go*, and then its pin is half orange, half red. An invite link lets exactly one person join; a second person who opens it is told it was already used.
**Depends on:** 13, 26

## Scope
- In: a new trip role `admin` (board admin) between planner and owner; per-trip spot kinds (name, color, order) that replace the fixed *Must go* / *Maybe* categories; a “Spot kinds” dialog for board admins and the owner; using kinds in the spot panel, pins, list, filter, sort, export, import and live updates; migrating existing spots; invite codes that are used up after one join.
- Out: textures or pictures per kind (a food or cat pattern filling the pin), which need their own step; uploading your own symbols; custom colors or renaming for *Home* and *Planned*, which stay fixed system states; invites that grant `admin` (invites still grant only planner or visitor, R-13-01); kinds shared across trips or trip templates.

## Current behavior
| Topic | Today |
| --- | --- |
| Categories | Fixed enum `spot_category` = `must_go`, `maybe`, `home` (`docs/database/schema.sql`, `packages/shared/src/spots.ts`). `planned` exists only in `display_category` |
| Colors | Fixed design tokens `cat-must-go`, `cat-maybe`, `cat-planned`, `cat-home` (`docs/DESIGN.md` §1) |
| Trip roles | `owner` > `planner` > `visitor`; only the owner manages members and invites |
| Invites | A code works for any number of people until it expires (7 days) or is revoked; `trip_invites.uses` only counts joins (`apps/api/src/members/store.ts`) |

## Decisions
| Topic | Decision |
| --- | --- |
| Who manages kinds | Board admins (new trip role `admin`) and the owner |
| *Must go* and *Maybe* | Become normal kinds that every trip starts with. They can be renamed, recolored, reordered or deleted like any other kind |
| *Home* and *Planned* | Unchanged: *Home* is a system category with stay periods and the primary home base; *Planned* is still automatic and shown over a spot's kind |
| Invite use | One code = one new member. Only a successful join uses it up; an existing member opening it changes nothing |
| Kinds per spot | 1 or 2 kinds per non-home spot. Two kinds show as a pin split half and half; more than two is not allowed because a split stops being readable |
| Deleting a kind still in use | The delete asks which kind the spots move to; moving the spots and deleting the kind happen in one transaction |
